3狀態樣式庫（空／載入／錯誤／成功）

同一塊區域，四種狀態各給實際樣式。切換觀看：這是全系統共用的狀態語彙，各頁不再各自發明。

四種狀態的規則：
空狀態必須說「為什麼空」＋「下一步可以做什麼」，不可以只放一句「沒有資料」。
載入中用骨架屏（skeleton）維持版面高度，避免內容跳動；不做旋轉圈以免看不出載入了什麼。
錯誤必須指到是哪一個欄位、為什麼被擋、怎麼修——這是 M2／M3／M5／M6／M7 所有守門的統一表現方式。
成功要給可追溯的 ID（需求編號／案件編號／工單編號），讓人能回頭查。

對外頁不得出現內部功能——四條實作要求
1. 後端過濾，不是前端隱藏——外部角色請求內部資料，後端直接不回傳（403／空集合），不是回傳後用 CSS 藏起來。
2. 對外頁不放任何指向對內頁的連結——M1／M2 上方的里程碑導覽已明確標示「展示導覽 · 僅預覽用 · 正式版不存在」。
3. 外部角色沒有 Users.id、沒有登入、沒有 access_key——他們是 PromotionPartners.partner_id，靠一次性連結或 Email 往返互動。
4. KOL 看不到別的 KOL——報價、聯絡方式、成效、款項一律 ◐ 只看自己那一份；候選名單與比價表永不外露。

5一致用語表（避免混稱）

同一件事只准有一種講法。左邊是對外／對內要說的詞，右邊是系統欄位與不要再說的詞。

正式稱謂角色／enum主檔與欄位 對外怎麼講❌ 不要再說
一句話記法：外部四角色（提案方／受邀 KOL／品牌／外包廠商）一律 PromotionPartners.partner_id； 內部同事一律 Users.id。看到欄位裡是 U-*** 就是自己人，看到 KOL-* / PROMO-TEST-PTR-* 就是外部合作方。 兩套 ID 永不互換、永不混用。
